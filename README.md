# avito_bot_detection

Детектор ботов по кукам: по логу событий пользователя за суточное окно наблюдения модель выдаёт score «бот / не бот». Решение построено на признаках поведения (ритм событий, курсор, User-Agent, разнообразие контента) и градиентном бустинге CatBoost.

## Задача и метрика

Для каждой куки (`cookie_id`) известно окно наблюдения `[window_start_ts, window_end_ts)` и события внутри него. Нужно предсказать вероятность того, что кука принадлежит боту.

**Метрика: Precision @ Recall ≥ 0.70.** Куки сортируются по score, перебираются все пороги, среди порогов с recall ≥ 0.70 берётся максимальный precision. Одинаковые score обрабатываются одной группой. Реализация лежит в [`metric.py`](metric.py) и совпадает с той, что использует проверяющая система. Дополнительно считается диагностическая `recall_at_fpr` (доля пойманных ботов при доле ложных срабатываний не более 1%).

## Данные

Файлы кладутся в папку `data/`:

| Файл | Содержимое |
|---|---|
| `train.csv` | куки с окнами наблюдения и целевой переменной `target` (≈ 11 тыс. строк, доля ботов ≈ 8%) |
| `test.csv` | куки с окнами без `target` (≈ 4.9 тыс. строк) |
| `events.csv` | лог событий (≈ 329 тыс. строк): тип события, платформа, User-Agent, координаты курсора, поиск, карточки |

Особенности данных, учтённых в решении:

- **Test идёт строго после train по времени**, поэтому валидация делается по времени, а не случайным разбиением.
- **Значения `platform` неоднородны** (`web`, `WEB`, `desktop`, `iphone` и т. д.), они приводятся к `web / android / ios`.
- **В `events.csv` есть полные дубли**, они удаляются.
- **Часть событий лежит вне окна наблюдения.** В обучении используются только события внутри окна. В train есть события после окна (в том числе все `captcha_shown`), в test их нет, поэтому они не должны попадать в признаки.


## Подход

1. **Предобработка.** Нормализация `platform`, удаление дублей, фильтр событий по окну наблюдения.
2. **Признаки** ([`features.py`](features.py), 93 фичи на куку):
   - объём и ритм: число событий, паузы между событиями, всплески, пиковая частота в минуту, ночная активность;
   - доли и счётчики типов событий, наличие контактов, избранного, логина;
   - разнообразие контента: доля топового объекта, уникальность `item_id`, категорий, локаций, запросов;
   - поиск и просмотры: глубина страниц, повторные просмотры, переходы поиск → карточка;
   - курсор: длина шагов, доля неподвижных точек, энтропия смещений и углов, признак «web без курсора»;
   - User-Agent и платформа: скриптовые UA, число разных UA, версии Chrome / Android / iOS;
   - возраст куки и время старта окна.
3. **Модель.** `CatBoostClassifier` с категориальными признаками `ua_browser`, `ua_os`, `platform`.
4. **Валидация.** Отложенная выборка из последних 3 дней train и `TimeSeriesSplit` на 3 фолда.
5. **Финал.** Обучение на всём train с числом итераций, найденным на отложенной выборке, предсказание на test и сохранение `submission.csv`.

## Результаты

Значения взяты из сохранённых выводов `solution.ipynb`.

| Отложенная (последние 3 дня train) | 0.724 | 0.600 | 0.929 | 0.785 |
| `TimeSeriesSplit`, среднее по 3 фолдам | 0.700 | 0.579 | 0.919 | 0.755 |
